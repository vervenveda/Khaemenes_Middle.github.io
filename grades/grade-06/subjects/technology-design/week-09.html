Week 09 · Technology, Design & Tools

Equations and Balanced Arguments

How do balance and evidence make arguments stronger?

Monday: Equations as constraints

Focus: Equations as constraints.

Learn: In a simple app, an equation can represent a constraint, such as remaining storage x plus used storage 7 equals capacity 20.

Practice and evidence: Solve x+7=20 and describe how a program would check the total.

Tuesday: Validate both sides

Focus: Validate both sides.

Learn: A tester substitutes a candidate value into an equation. For 3x=12, x=4 because both sides evaluate to 12.

Practice and evidence: Create an input-output test table for 3x=12, including one invalid candidate and helpful feedback.

Wednesday: Debug an equation solver

Focus: Debug an equation solver.

Learn: A bug occurs if software changes only one side of an equation. A valid inverse operation applied to both sides preserves equality.

Practice and evidence: Write an original paper debugging case for x−5=8, showing the incorrect and corrected steps.

Thursday: Design accessible feedback

Focus: Design accessible feedback.

Learn: Errors should explain the mathematical difference, not insult a learner. A 255px interface needs readable labels, visible focus and a text error description.

Practice and evidence: Sketch a narrow-screen equation checker with input, check button, equation and constructive message.

Friday: Prototype certification

Focus: Prototype certification.

Learn: Testing should include correct solutions, incorrect solutions, missing values and nonnumeric input.

Practice and evidence: Submit a paper prototype, four test cases, and a revision log. Rubric 20: equation correctness 6, tests 6, access 5, documentation 3.
