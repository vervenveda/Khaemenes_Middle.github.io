Week 08 · Technology, Design & Tools

Expressions and Algebraic Thinking

How can symbols represent ideas in math, language, and culture?

Monday: Variables in simple programs

Focus: Variables in simple programs.

Learn: A variable stores or refers to data. In a local script, count=3 followed by total=2*count yields 6; the value and its meaning should be documented.

Practice and evidence: Write a paper algorithm that accepts a number n and produces 2n+3, including examples n=0 and n=4.

Tuesday: Spreadsheet expressions

Focus: Spreadsheet expressions.

Learn: In a spreadsheet, a formula such as =2*A2+3 evaluates using the number in cell A2. Arithmetic grouping is important: =2*(A2+3) gives a different result.

Practice and evidence: Fill a test table for A2=1, 2, 4 comparing the two formulas and explaining mismatches.

Wednesday: Debug operator order

Focus: Debug operator order.

Learn: Without correct parentheses, an expression can implement the wrong algorithm. For x=2, 3*(x+4)=18, whereas 3*x+4=10.

Practice and evidence: Write two minimal test cases that reveal the mistake and document the repaired expression.

Thursday: Validate input responsibly

Focus: Validate input responsibly.

Learn: An interface should distinguish empty, numeric and nonnumeric inputs, provide an explanation, and avoid collecting unrelated personal data.

Practice and evidence: Sketch a small 255px-wide algebra calculator with labeled input, readable output, error state, and keyboard navigation.

Friday: Test a reusable calculator

Focus: Test a reusable calculator.

Learn: A robust prototype documents its formula, valid inputs, boundary cases and any revisions.

Practice and evidence: Submit your paper algorithm, three test cases, an accessible wireframe and a debug record. Rubric: formula 6, testing 5, access 5, documentation 4.
