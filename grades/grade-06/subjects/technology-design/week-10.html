Week 10 · Technology, Design & Tools

Inequalities and Decision Rules

How do constraints shape solutions and decisions?

Monday: Translate a constraint into code

Focus: Translate a constraint into code.

Learn: A program can check whether a number meets a limit: count<=20 is true for count=20 and false for count=21. Explain the rule in human-readable language.

Practice and evidence: Write an offline paper algorithm that accepts count and reports whether count≤20.

Tuesday: Test boundary values

Focus: Test boundary values.

Learn: A reliable validator tests below, at and above a threshold. For x<10, 9 passes, 10 fails, and 11 fails.

Practice and evidence: Make a table testing x<10 and x≤10 at x=9,10,11; explain the different outcome at 10.

Wednesday: Validate input

Focus: Validate input.

Learn: A rule checker should not accept blank or nonnumeric values as meaningful measurements. It should explain the issue without insulting the student.

Practice and evidence: Sketch a labeled input form with separate friendly messages for empty, invalid and out-of-range entries.

Thursday: Consider accessible interfaces

Focus: Consider accessible interfaces.

Learn: At 255px width, large tap targets, wrapping labels, clear contrast and keyboard focus improve a rule checker's usability.

Practice and evidence: Design a narrow-screen interface including a textual result instead of relying only on red and green colors.

Friday: Prototype rule certification

Focus: Prototype rule certification.

Learn: Testing a program requires documenting intended behavior, observed outputs and a change log.

Practice and evidence: Present pseudocode, six test cases, a 255px wireframe and one bug fix. Rubric: logic 6, boundaries 6, access 5, documentation 3.
