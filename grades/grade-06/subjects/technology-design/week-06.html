Week 06 · Technology, Design & Tools

Rational Numbers and Ancient Number Systems

How have cultures represented numbers and meaning across time?

Monday: Represent signed input

Focus: Represent signed input.

Learn: Software distinguishes −5 from 5 and sometimes distinguishes a hyphen from the mathematical minus symbol. A data field should explain valid inputs and units.

Practice and evidence: Sketch a temperature-entry form accepting −10, 0 and +6 °C, with a readable label and clear error message.

Tuesday: Encode historical numerals

Focus: Encode historical numerals.

Learn: A parser converts a representation into a number. In an introductory Roman numeral subset, I=1, V=5 and X=10; XIV means 14. Rules beyond this subset require explicit specification.

Practice and evidence: Build a three-row test table for IV=4, IX=9, XIV=14 and describe one input your parser does not support.

Wednesday: Validate number input

Focus: Validate number input.

Learn: A validator checks allowed characters, range and meaning. Incorrect entries should receive helpful explanations instead of silently changing data.

Practice and evidence: Design five test cases for an integer-temperature input, including negative, zero, positive, empty and nonnumeric examples.

Thursday: Design accessible labels

Focus: Design accessible labels.

Learn: A narrow interface should preserve signs, units and error messages with contrast, keyboard focus and unclipped text.

Practice and evidence: Sketch a responsive 255px number-system converter with visible input label, convert action, output and explanation.

Friday: Test documentation

Focus: Test documentation.

Learn: A repeatable tool requires defined scope, example conversions, edge cases and documented corrections.

Practice and evidence: Present a paper converter, a five-case validation log and a privacy-safe instruction card. Rubric: representation 6, validation 6, accessibility 5, revision 3.
